# 多屏窗口不可见问题检查记录

## 现象与结论

用户反馈：切换显示器、放大窗口后，任务栏仍有程序，但整个窗口不可见。

已确认并修复以下相关缺陷，尚不能认定覆盖所有驱动、远程桌面及显示器组合。

| 缺陷 | 影响 | 修复 |
| --- | --- | --- |
| 仅在读取配置时校正窗口位置 | 运行时切屏、工作区变化、还原窗口后，屏幕外的位置不会重新检查 | 监听显示器、工作区、DPI、窗口屏幕及窗口状态变化；延迟 150 毫秒等待 Qt 完成调整后检查 |
| 将外框尺寸和坐标传给内容区定位接口 | 重复校正会继续增大窗口并向左上移动，标题栏可能越界 | 区分外框定位和内容区尺寸，预留边框与标题栏空间 |
| 按窗口中心选择屏幕，找不到时直接回主屏 | 窗口中心落在屏幕间隙时可能选错屏幕 | 优先选择与窗口相交面积最大的屏幕，支持负坐标 |
| 展开面板后的延迟高度恢复只检查展开前状态 | 用户已经最大化时，回调仍可把窗口高度改成旧值 | 同时检查当前状态，并约束普通窗口高度不超出工作区 |

最小化和隐藏的窗口不会因显示器事件被主动弹出。正常最大化、全屏的几何形状继续由窗口管理器处理。

坐标处理参考 [Qt QWidget 窗口几何定义](https://doc.qt.io/archives/qt-5.15/qwidget.html#window-geometry)。

## 验证

- 新增测试中的最初 8 个复现场景在修复前均失败，修复后通过。
- `tests.test_window_placement`：11 项通过，覆盖重复校正、屏幕外窗口、负坐标、切屏、工作区和 DPI 事件、最大化还原、最小化、隐藏、全屏及延迟回调。
- `tests.test_multi_send`：58 项通过。
- `tests.test_ui_regressions`：63 项通过。
- 本机 Windows 双屏实测：主屏工作区 `(0, 0, 2560, 1392)`；左侧副屏工作区 `(-1920, 0, 1920, 1140)`。两屏分别完成窗口移动、面板展开、最大化、收起及还原；另验证展开后跨屏最大化再收起，以及屏幕外位置找回。
- 查看两屏测试过程中保存的窗口截图，未发现内容空白或主要控件消失。
- 语法检查与 `git diff --check` 通过。

原多字符串测试有一项要求保留超过屏幕的高度，现改为检查完整外框处于工作区内；保留正常高度的测试使用可容纳的窗口尺寸。测试清理时显式处理 Qt 延迟删除事件，避免遗留测试窗口及定时器干扰后续用例。

## 范围与交付

拔屏、主屏变更和 DPI 变化通过 Qt 信号模拟验证，未进行物理拔插或修改系统缩放设置。没有进行串口硬件、OTA 或整项目全量测试。

修复位于 `serial_GUI.py`，回归用例位于 `tests/test_window_placement.py` 和 `tests/test_multi_send.py`。本次未生成新版 exe，现有安装包需要重新构建才能包含修复。
