# 界面与功能检查记录

## 已复现并修复

| 优先级 | 问题 | 原因与修复 |
| --- | --- | --- |
| 高 | UDP 报文接收失败或被截断 | `in_waiting` 返回 1，接收线程据此申请 1 字节缓冲区；Windows 下较长报文读取失败后又被忽略。现按最大 UDP 报文预留接收空间。 |
| 中 | TCP 客户端逐字节读取，吞吐低、界面刷新过碎 | 同样把可读标志 1 当作缓冲大小。现每次最多读 4096 字节。 |
| 中 | 串口读取异常没有反馈 | 传输层把 `SerialException` 转为空数据。现交给接收线程上报，触发既有断开与错误提示。 |
| 中 | UTF-8、GBK 等中文跨数据块时乱码 | 每个数据块独立解码。现使用增量解码器，保留尚未收齐的字符；切换编码、HEX 显示、连接或清空接收区时重置。 |
| 高 | 恢复 UDP/TCP 配置后连接按钮缺失或显示错误 | 配置只恢复模式索引和参数页，没有同步两套按钮的显隐。现统一手动切换与配置恢复的界面更新逻辑，保留已保存的网络端点。 |
| 中 | 连接读取出错后无法切换通信模式 | 错误恢复漏启用模式选择框。现恢复启用状态。 |
| 高 | 文件发送过程中断开重连，旧任务可能继续发送 | 断开时没有取消文件任务。现主动取消，并在取得传输锁后再次检查，防止等锁期间连接已改变。 |
| 中 | 文件被截短后仍提示发送成功；文件增长后可能多发 | 提前遇到文件结尾直接按成功返回，读取块也未限制剩余字节数。现校验实际读取长度，并限制到任务启动时的文件大小。 |

新增 `tests/test_functional_audit.py`，包含 12 项测试。最初的 9 项复现测试在修复前均失败；另外 3 项覆盖解码器状态重置、正常文件发送和等锁期间取消。

全量检查还发现上轮测试清理调整导致主题测试先销毁父窗口、后执行子窗口清理。已把 Qt 延迟删除安排在子窗口清理之后；10 项主题测试恢复通过。这属于测试生命周期问题，不记为产品缺陷。

实现参考：[Python socket 接口](https://docs.python.org/3/library/socket.html#socket.socket.recvfrom)、[增量解码器](https://docs.python.org/3/library/codecs.html#incremental-encoding-and-decoding)。

## 仍需处理的代码检查项

TCP 客户端建连仍由 `SerialTool.toggle_connection` 在界面线程直接调用 `TransportWrapper.open_tcp_client`，后者使用阻塞的 `connect`，超时设为 5 秒。慢网络、连接超时或 DNS 等待期间可能导致界面短暂不响应。此次未改为异步建连，也未实测外部网络超时；该项需单独覆盖取消连接、退出期间回调和快速重连的生命周期。
